# 基础检查与验收

页面制作与修改后必须执行基础检查：**完成页面 → 基础检查 → 修复并复查 → 展示给用户验收**。不为基础检查生成 Rubric 分数。普通自检仍须发现并处理明显的事实、布局和交互错误。

仅在用户明确要求打分、评分或执行 Rubric 时，额外加载 [Rubric Evaluation](rubric-evaluation.md)。“检查一下”“看看有没有问题”“优化一下”不自动触发评分。评分不替代基础检查或用户验收。

## 检查范围

- 新页面：当前页默认状态及本次实现涉及的关键交互状态。
- 页面修改：受影响页面和状态。
- 页序、入口或共用逻辑变化：扩大到实际受影响范围。
- 整套制作完成：补充整体页序、入口和内容对应检查。
- 仅修改 Skill 文档：运行 `check.skill creator-skill` 并核对引用，不启动页面检查或评分。

基础检查必须执行，不等于每次运行全部工具。按实际改动选择适用项；不适用时说明原因。检查证据须对应当前实现，旧截图和旧统计不能证明新版本通过。

## 必须覆盖的检查

### 工程与模块

准备交付时运行[course.pack](../engineering/delivery.md)。Python结构与文件检查先执行；环境齐全时默认执行原有Node资源、编辑ID、类型、本地构建和真实浏览器检查。缺依赖按[本地环境与窗口](../engineering/local-environment.md)只问一次并保存意愿；用户拒绝时继续可执行部分，缺证据标未验证，不通过降低检查范围来消除确定错误。

检查课程/页面UUID、入口与大纲、PPT、Guide、讲稿的对应关系；页序或双入口变化时扩大到受影响范围。打包、改引用和补编辑ID仅处理交付副本，原工程与Shared保留。服务器独立复核入库、安全与正式构建，不能把本地报告当作服务器通过。

核对页面框架：第一页不使用 `ContentBlock`；其余页面使用 Shared `ContentBlock` 及标准标题区，或有用户对当前范围明确指定的其他版式。设计图和实现均需符合这一要求。

核对所有设计示意图与正式页面画布均无页码、总页数或页序角标；参考原稿中的页码也不得带入。

核对实现分层：所有可见文字须能定位到 React 渲染的 `Typography`，知识图表须能定位到 React/SVG/Canvas 或项目图表组件；图片只承载插画、照片、纹理等素材。禁用图片层后，标题、正文、步骤编号、图表及标签仍须完整存在并保持布局。整页设计图、隐藏文字副本、透明文字覆盖或图片裁片承载文案/图表，均判定不通过，视觉相似不能豁免。

### Shuku 可视化编辑兼容性验收

更新已有课程、迁移旧课件，或准备交付需要普通编辑能力的课程时，在本次交付副本与对应的最新构建产物上执行 `check.source-editing`。补齐编辑 ID 或编译成功，均不能单独证明可视化编辑可用。

1. **排查旧脚本阻断**：检查课程内的 `shuku-visual-edits.json`、`shuku-visual-edits-runtime.js` 及其入口依赖。存在时先核对并迁移有效的文字、图片修改，再移除旧文件与依赖；不得直接删除以丢弃原有编辑，也不得伪造版本能力字段。
2. **核对实际版本能力**：复用指定 Shuku 运行时的 `SourceEditor` 与 `detect_build`，确认课程、页面 ID 和构建页序一致，模型未阻断、有可替换绑定，且本次构建的 `supports_source_edit` 为 `true`。静态标记必须实际进入产物，未使用源码中的标记不能当作运行证据。
3. **文字／图片替换往返**：仅在内存副本调用实际编辑器。文字替换后按同一 ID 重新解析并恢复原文；图片用小型测试 WebP 往返替换，核对资源字节与绑定保留。原始课程文件和图片不写回。某类不存在可替换绑定时说明“不适用”，不得把它说成已验证。
4. **隔离 iframe 实际选中**：以本次构建入口加载页面，注入对应 Shuku 的真实编辑运行时，通过 `postMessage` 配置真实绑定。对可见文字／图片实际点击，收到匹配 ID、类型的 `selected` 事件后才算通过；DOM 中存在属性不等于可选中。异步加载早期的 `rendered=true、marked=0` 不是最终失败证据，应等待页面与绑定就绪。记录所查页面、样本和截图；默认最多查找 12 页，未找到可见样本时标记“未验证”，按课程补充操作或提高 `--max-pages` 后复查。

`course.pack --checks auto` 由 `scripts/module/local_validation.py` 自动调度；确定的旧脚本、无效能力或替换错误阻止出包。缺少 Shuku Python 运行时、对应构建、解析依赖或浏览器时保留可执行的检查，其余标记“未验证”，不得降级成“通过”。仅有大纲时不适用。结果只证明本地已执行的能力，不代替服务器入库、审核、发布或全部交互验收。

```powershell
python creator-skill/scripts/tools.py check.source-editing --project <工程绝对路径> --module <课程UUID> --shuku-root <Shuku源码绝对路径> --build-output <本次构建输出绝对路径> --evidence <检查证据目录>
```

退出码：`0` 为所需检查均通过（不存在的元素类型可不适用）；`1` 为确定不通过；`2` 为存在未验证项或执行条件不足。`--skip-browser` 必须将 iframe 选中标记为“未验证”，不能用来宣称完整通过。

### 页面渲染与边界

确认页面能加载，实际页 ID 与目标一致，逻辑画布为 1600×900；等比例缩放后的显示尺寸不作为逻辑画布错误。检查元素越出画布和容器内部的文字、内容溢出，两者分别记录。

有意设计的代码区、列表等内部视口与整页内容溢出区分。例外须明确用途、可追踪，且视口本身不能越出画布。不允许通过裁切或横向滚动掩盖本应完整展示的内容。

检查默认状态与受影响的关键操作状态。获取并实际打开真实页面截图，核对脚本难以可靠判断的遮挡、字形截断、异常加载和内容错误；查看截图不要求打分。设计图不能替代实现截图。

把同一页、同一状态的设计示意图和实际画布截图等比例对齐，并排或叠加核对。逐项检查构图、关键元素边界、相对位置、尺寸、对齐、间距、文案及换行、字号字重、配色、图形、素材和控件状态。局部修改还须检查改动周围及整页构图。逐一实际操作核心交互，并对照设计稿或设计说明中的关键状态。视觉一致性是验收硬门槛。发现未获授权的可见偏差，修正后重新截图对照；偏差仍存在或证据不足时，当前页不得标记完成、通过或作为最终成品交付。

用户跳过设计确认时，以已展示的设计稿为对照，注明其确认状态。用户明确同意省略示意图时，以已展示的文字方案核对关系、主图和关键状态，并注明没有设计稿。适用的对照证据无法获取时，将对应项标为未验证。

### 字数与明确限制

每个被检查页面、每个被检查状态都须输出字数及统计口径。`capture.slides` 返回当前状态的 DOM 字符统计：中文、英文字母、数字、标点各按一个非空白 Unicode 码点计数，空白不计；文本节点只遍历一次，隐藏文本和画布外播放器、讲稿不计；可见文本输入值和选中项单列并计入总数。密码及非文本控件不计。

此口径不是 OCR，也不等于完整页面的精确字数：图片、Canvas、视频和 CSS 生成文字未覆盖，输入框值可能包含被裁切部分，具体限制随结果返回。默认状态与操作后状态分别统计，不相加。`analyze.pages` 的源码近似统计仅作补充，不能冒充当前渲染统计；日常检查不要求生成 HTML 报告。

有用户或项目明确上限时，通过 `--max-chars` 按该口径筛查；任务另有计数口径时单独核对并注明。没有上限时照常报告数量，不自行设置统一门槛或判定超限，不因字多自动删减已确认内容。缺少结果、无法匹配页 ID 或仅有无法读取文字的媒体页面，标记未验证，不记为零字或通过。未覆盖文字涉及明确上限时，须补充人工核对，不能只凭 DOM 计数判定完整内容符合限制。

### 相关交互与内容

实际验证本次涉及的核心操作、重置及必要的等待、失败等分支，核对输入、图形、数值、公式和反馈是否对应。能复算的数据优先复算，明显事实错误须处理。截图不能单独证明交互行为正确；无法执行或缺少证据时标记未验证。

## 工具与覆盖范围

course.pack默认按能力调度下列原有工具；每次报告实际执行与未覆盖范围，不必人工逐条串联。已有工具也继续支持单独调用。Node或浏览器缺失时按持久化意愿补依赖，不能每次重复询问。完整参数见[工具索引](../tools.md)。

| 工具 | 覆盖范围与限制 |
|---|---|
| `check.module` | 元数据、页 ID、身份及字面量入口、资源引用；动态表达式仍需实测。身份变化补充 `module.identity --check`。 |
| `check.asset-imports`（Node） | 只读检查本地媒体引用、缺失文件与目录越界；新课程素材仍使用 moduleAssetUrl。 |
| `check.course` | 大纲、PPT 与 Guide 的实际页序、标题及讲稿对应；不存在的入口按任务说明不适用，无法读取的应标记未验证。 |
| `check.source-editing` | 旧脚本、实际 `supports_source_edit`、编辑器内存替换往返和 iframe 真实选中；依赖或样本缺失时标记未验证，不写课程源码。 |
| `capture.slides` | 复用页面就绪检查、真实截图及 `--actions` 动作；每页状态的 `checks` 返回边界、字数、警告和覆盖限制。截图与字数仍需核对。 |
| `check.bounds`（Node） | 通过已有 Chromium 调试会话检查新开页面的默认状态；验证就绪与页 ID，返回相同的边界、字数口径。交互状态优先复用 `capture.slides`，不另设动作格式。 |
| `analyze.pages`（Node） | 可选的离线源码近似统计与分布报告；不证明当前状态。 |

日常页面检查可使用：

```powershell
python creator-skill/scripts/tools.py capture.slides --module <模块名> --slide <页ID> --page-directory <语义页目录>
```

关键状态沿用同一命令的 `--actions <动作JSON> --state <状态名>`；仅明确存在字数上限时添加 `--max-chars <上限>`。动作只能覆盖任务已授权的操作。逐页产物保存在 `pages/<语义页目录>/_scratchpad/`；读取截图并核对交互后再形成结论。

几何脚本检查容器滚动尺寸与元素矩形，不能证明不存在遮挡或所有字形截断。未声明例外的裁切、滚动容器发生尺寸超限时报告错误；`overflow: visible` 的尺寸超出和字体边缘可能来自正常排版，单列风险警告，结合截图判断。`data-ppt-viewport="用途说明"` 仅用于真实内部裁切/滚动视口，脚本输出对应例外；不得给整张画布加例外，也不得把本应完整展示的正文标作例外。例外不豁免视口内其他容器的裁切错误。省略字数阈值时，结果中的 `maximum` 与 `exceeded` 为 `null`。

## 修复、结束与受阻处理

按“检查 → 定位问题 → 局部修复 → 复查受影响项”推进。问题写明页 ID、状态、元素、实际表现及判断依据。警告属于启发式风险提示，与确定性错误分列，不能将风险数量当作违规数量。

| 结果 | 含义 |
|---|---|
| 通过 | 已执行且满足对应要求。脚本通过仅覆盖它实际检查的部分。 |
| 不通过 | 已发现明确违规。 |
| 未验证 | 缺少执行条件、证据或工具覆盖。 |
| 不适用 | 当前任务不存在该检查对象，并说明原因。 |

CLI 退出码 `0` 表示已执行工具范围内通过，`1` 表示发现违规，`2` 表示执行错误或存在未验证项；同时读取 JSON 的状态、错误和覆盖限制。浏览器、服务或依赖缺失时先诊断与修复，不能自动免检；仍受阻时说明缺少的条件、未验证范围和下一步。

必需项通过后展示真实效果，按当前 Workflow 进入用户验收。必需项不通过或未验证时明确剩余问题，不声称全部通过。同一问题反复修复无进展时停止盲目重试并说明阻碍，不用固定返工次数代替完成标准。用户后续修改不受自检轮数限制。

默认简短说明检查范围、结果和剩余问题，不强制生成 HTML、评分表或过程文档。

## 报告问题与检查阻碍

将本次新引入的问题、经过基线对照确认的原有问题、环境错误和未验证范围分开说明。没有同条件的基线证据时，只报告观察到的问题，不擅自归因为旧错误。既有错误仍须展示，不能因它们不是本次引入就声称工程整体通过。

模板类型检查报告 `newIssues`、`existingIssues`、`environmentErrors`、`unverified` 和实际覆盖范围。出现新问题时返回失败；只有依赖工程的既有错误时标记 `blocked`；缺少配置或编译器时标记执行错误。测试验证报告归因正确，不代替完整工程的类型检查。页面自检与用户验收继续执行各自的要求。
