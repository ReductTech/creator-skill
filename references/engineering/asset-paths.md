# 素材引用路径迁移

## 作者默认流程：按环境选择完整迁移能力

交付时只运行 [course.pack](delivery.md)。工具先转换媒体，再使用本次真实 source→target 映射迁移临时副本中的引用，检查并归档；不要求智能体手工串联压缩、改名、查漏和打包，也不修改作者原工程。Node及TypeScript可用时优先复用原有assets.rewrite的完整规划器，支持其静态与可确定动态迁移；否则使用下表的Python补充能力。

| 引用 | 自动处理 |
|---|---|
| JS/TS/JSX/TSX完整字符串与无插值模板 | Python Tree-sitter 解析后按真实课程路径匹配，注释不当作代码 |
| JSON/glTF字符串值 | 仅迁移匹配路径，保留文件格式与其他值 |
| CSS `url()`、`@import` | 迁移完整路径，保留查询参数与片段 |
| HTML/XML/SVG 的 src/href/poster属性、Markdown链接 | 处理完整资源地址 |
| 动态 helper、路径拼接、模板插值、复杂封装与外部数据 | 不执行表达式、不猜测；报告文件、行号与表达式，必要时阻止出包 |

转换目标已有不同文件、相同引用有多个可能目标或源码语法不完整时，不覆盖、不随机选择。报告记录原路径、成品路径与问题位置。图集尺寸保持，SVG原样保留，音视频与图片使用同一迁移机制。

## 智能体处理报告

1. 先读 stdout 的统计和问题；不足时读取同级完整 `.report.json` 的 `media.conversions`、`media.references.records` 与 `issues`。
2. 按原课程逻辑路径定位源码；检查实际消费者和动态数据，将引用改为完整真实路径，动态切换用固定路径列表。转换发生在临时副本，不把临时路径写进源码。
3. 修复原源码后重新运行 course.pack。静态改写成功只证明已覆盖结构，按影响范围验证真实加载和交互；缺少运行环境时说明未验证。

## 可选开发者工具

已有 `assets.compress` 与 Node版 `assets.rewrite` 仍用于明确要求原地维护素材的开发者任务，原有规划器同时供自动打包复用。前者保留原图，后者默认预览、`--apply` 才改源码并备份到所属课程 `_scratchpad/`；不修改 Shared。使用同次转换报告的 `converted` 映射，不按全库扩展名替换、不改跳过素材。参数用 `describe` / `--help`，Node版迁移需 TypeScript。完成原地维护后按范围检查静态引用和真实加载，再清理临时记录。

修复动态引用时，先在作者源码中枚举原工程实际存在的完整输入路径；course.pack会在副本中改为成品路径。不要把临时副本中的目标路径提前写进没有该文件的原工程。
