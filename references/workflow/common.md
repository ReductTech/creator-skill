# 流程共用说明

## 接续与确认

读取最新大纲、相关页面与对话确认记录，定位当前阶段：待设计、待设计确认、待实现、待验收或已完成。沿用当前 Workflow，不因已有代码、图片或可运行页面推断用户认可；只在缺失信息会阻碍下一步时澄清。

每页按“ImageGen设计图 → 用户确认 → React实现与自检 → 用户验收”推进，当前页验收后开始下一页。用户明确改变流程或授权连续制作时，只在该范围内调整。工具边界与 prompt 见[设计](../design/design.md)，两种工作流只补充起点差异。

确认只覆盖实际认可的版本和范围。核心内容、构图或交互实质变化时重新设计并确认受影响部分；文字、间距等局部修正可直接实现。局部任务保留其他成果，不重新审批整份演示。

## 自检、交付与清理

实现或修改后按[基础检查](../eval/checks.md)核对当前版本与相关状态，展示真实效果后进入验收。缺少渲染/交互证据标记未验证，自检通过不代表用户认可。用户要求评分时再读 Rubric。

需要源码交付时直接运行一次 [course.pack](../engineering/delivery.md)：自动准备媒体、迁移可确定引用、检查并出包，报告不确定路径供智能体修复；不要求手工串联前置工具，默认按环境执行原有Node检测、本地构建和浏览器检查，不上传。上传按已有授权和目标平台规则处理。

每页核对与验收完成后，运行 `scratchpad.clean <该页目录> --apply`；创作收尾或提交前再清理本次课程。先转存需保留的设计、正式素材和记录。续作可从正式位置及对话记录接续，不必重建已清理的证据。仅打包时只排除临时目录，不清理原工程。
