# 流程共用说明

## 接续与确认

读取最新大纲、相关页面与对话确认记录，定位当前阶段：待设计、待设计确认、待实现、待验收或已完成。沿用当前 Workflow，不因已有代码、图片或可运行页面推断用户认可；只在缺失信息会阻碍下一步时澄清。

默认逐页推进：准备设计图，请用户确认设计，完成 React 实现与自检，再请用户验收。用户明确要求跳过逐页确认、按批次验收或直接连续制作时，跳过授权范围内的设计确认和/或逐页验收等待，仍逐页自检。已跳过的节点不记为用户已确认。快速口令如“这几页直接做完给我看”适用于指定页面；没有包含在授权内的确认节点按默认流程处理。

确认只覆盖实际认可的版本和范围。核心内容、构图或交互实质变化时重新设计，并按当前授权确定是否需要确认。文字、间距等局部修正可直接实现。局部任务保留其他成果。设计准备及无生图工具时的处理见[设计](../design/design.md#视觉设计图的工具约束)。

## 自检、交付与清理

实现或修改后按[基础检查](../eval/checks.md)核对当前版本与相关状态，按约定逐页或集中展示真实效果。缺少渲染/交互证据标记未验证，自检通过不代表用户认可。用户要求评分时再读 Rubric。

需要源码交付时直接运行一次 [course.pack](../engineering/delivery.md)：自动准备媒体、迁移可确定引用、检查并出包，报告不确定路径供智能体修复；不要求手工串联前置工具，默认按环境执行原有Node检测、本地构建和浏览器检查，不上传。上传按已有授权和目标平台规则处理。

每页核对完成且已通过约定的验收节点后，运行 `scratchpad.clean <该页目录> --apply`；用户跳过验收时，完成核对即可清理。创作收尾或提交前再清理本次课程。先转存需保留的设计、正式素材和记录。续作可从正式位置及对话记录接续，不必重建已清理的证据。仅打包时只排除临时目录，不清理原工程。
